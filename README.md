## Project Overview

**TrainerCraft** is a real-time bridge system designed to translate telemetry data from physical smart bike trainers or standalone sensors (**Bluetooth Low Energy - CSC Profile**) into virtual game environments. Speed generated by pedaling in the real world is mapped directly to entity or vehicle movement in-game.

---

## System Architecture

Data pipeline from hardware sensor to game runtime:

```text
[ BLE Speed Sensor / Trainer ]
               │ (Bluetooth CSC Profile)
               ▼
   [ Flutter App Bridge ] ──► (Local WebSocket Server: 8000)
                                       │
                                       ▼
                       [ Minecraft Bedrock Edition ]
                       └── Script API (main.js) ──► Dynamic Entity Movement

```

1. **Hardware / Simulator**: Emits standard BLE CSC (*Cycling Speed and Cadence*) byte packets.
2. **Flutter App Bridge**: Ingests the BLE stream, calculates real-time velocity ($km/h$), and broadcasts telemetry payloads via a local WebSocket server.
3. **Minecraft Add-on (Script API)**: Listens for incoming `scriptevent` payloads over the WebSocket connection and continuously overrides the target bike entity's `movement` component.

## Getting Started

### 1. Run the Python BLE Peripheral Simulator (Debug Mode)

To debug without physical hardware, spin up the GATT server on your development machine:

```bash
pip install bluez-peripheral
python debug/debug-csc.py
```

### 2. Build & Launch the Flutter App Bridge

Deploy the bridge app to your mobile device:

```bash
flutter clean
flutter run
```

### 3. Install the Minecraft Bedrock Add-on

1. Go to the 
2. Open **World Settings** in Minecraft Bedrock:
* Enable **Behavior Pack: TrainerCraft BP**.
* Toggle **Beta APIs / Experimental Features** to **ON**.
3. In-game, spawn the vehicle and establish the WebSocket handshake:
```text
/summon trainercraft:bike
/wsserver localhost:8000
```

## Multi-Game Modding Guide

TrainerCraft is architected with a decoupled engine design. The **Flutter App Bridge handles data ingestion and output broadcasting independently**, allowing developers to create custom connectors for any game engine supporting sockets, IPC, or memory manipulation.

### Integration Approaches for Other Games:

#### 1. Games with Socket/WebSocket Support (e.g., Roblox, Assetto Corsa via Plugins)

* Implement a WebSocket listener in the game's scripting layer connecting to the App Bridge IP.
* Parse the incoming JSON payload (`{"speed": 25.4}`).
* Apply the speed scalar directly to the vehicle's RigidBody or physics controller.

#### 2. Native Native Single-Player PC Games (e.g., ETS2, GTA V)

* Build a lightweight intermediary plugin (C++ / C# via DLL Injection or Memory Hooks).
* Read stream telemetry from TrainerCraft's WebSocket server.
* Write the calculated velocity straight into the player vehicle's active memory address.

#### 3. Virtual Input / Emulated HID Controllers

* Map the telemetry stream to virtual joystick/gamepad inputs (e.g., mapping pedal rotation frequency to analog trigger values like RT/Gas).
